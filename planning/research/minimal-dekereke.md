## Summary

What it does have is two well-established optional-feature idioms — module-level `try: import X / except: X=None` plus a `program['nosound']`-style flag (io_put/sound.py:18-25, main.py:53-67), and function-local try-import-then-return (io_put/xlp.py:91-95) — which are the correct template for making a Dekereke module a deletable no-op. The minimal-diff design is smaller than the draft plan assumes: because the new-project pipeline already runs code→verify→write, the entire flow is reusable by changing ONE hard-coded class reference at frontend/ui_shell.py:3170, plus one row in `LiftChooser`'s optionlist (ui_shell.py:3421-3432), one `elif` in `setfilename` (ui_shell.py:3356-3375), and a 16-line `Dekereke(WordListTemplate)` appended to the 100-line backend/core/templates.py. tests/test_import_smoke.py needs no edit at all (it rglob-discovers modules, lines 58-79), contradicting plan §5. io_put/lift.py must not be touched: `addentry` (lift.py:333) calls `self.write()` on every entry (lift.py:377), so a 944-record import would serialize the whole LIFT 944 times — the converter must emit a finished .lift and then hand it to `lift.LiftXML(path, tostrip=True)`, mirroring io_put/cawl.py:18 exactly. I verified that reusing the CAWL flow unchanged is safe: `fill_db_images()` no-ops per sense for a non-CAWL db (lift.py:2341 → 3398 `if not self.word_list_n: return False`). The big non-technical risk is that Kent already answered this exact request and declined the general case in issue #165 (closed 2026-04-01), saying "I'm not likely to write transforms for this or other XML specifications any time soon" while insisting LIFT is the interchange point — and no human outside contributor has ever landed a PR (all 168 PRs are his own branches, gitlocalize/Crowdin bots, or two dependabot PRs he closed).
