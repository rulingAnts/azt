# Research: africa

_Auto-captured from the 2026-09-02 research workflow._

## Summary

A-Z+T's ANALYTIC CORE is genuinely language-general; its DATA-COLLECTION SHELL, DOCS, and DEFAULTS are Africa-shaped. The CV-profile engine (utilities/rx.py + backend/core/profiles.py) imposes no CV(C) template: I instantiated its RegexDict directly with a Fayu-like inventory and got 'tiaure'→'CVVVCV', 'uai'→'VVV', 'ᵐbou'→'CV', 'kwai'→'CV' — arbitrary vowel sequences, complex onsets, prenasalised stops and labialised Cw all analyse correctly once the polygraph inventory is right. The syllable model (backend/core/analysis_inputs.py) is better than merely general — it explicitly encodes the vowel-sequence ambiguity Papuanists care about (profile_syllable_range returns a [vowel-sequences .. individual-vowels] range, so 'CVVCV' is legitimately 2 OR 3 syllables), derives everything from three theory-neutral primitives (#C / C# / syls), and allows C-clusters and V-runs up to 3 with a free-entry escape hatch. Tone is theory-neutral: sorting yields same/different piles and cross-frame equivalence classes, and the report text explicitly disclaims assigning values; tone LABELS use Chao 5-level letters with real contour interpolation in the beep synthesiser, so contours and more than three levels are representable. There is NO ATR, no vowel harmony, no live noun-class machinery, and no 7-vowel assumption anywhere. Fayu's inventory (i u o ɛ a, β) is fully covered by the hardcoded segment lists and the alphabet feature tables. The problems are elsewhere: the polygraph CANDIDATE list is closed and English/French/Cameroon-shaped (missing 'ia','ua','ao','io','iu','ui'); the VV interpretation is a single global binary that the UI mis-describes as same-letter-only when the code applies it to any V+V; the new-project template is hardcoded to the Comparative African Wordlist with no other WordListTemplate subclass; automatic illustrations are keyed to a hardcoded 'SILCAWL' LIFT field; the parser only handles concatenative prefix/suffix morphology recovered as the longest common contiguous substring of citation vs. plural (nouns) / imperative (verbs); and there is a live crash — WordCollection.dobuttonkwargs formats '{}' with .format(count=…), so for ANY database missing CAWL tags (i.e. every Papua project) it raises IndexError, is swallowed by a bare except in ui_shell, and the primary 'Add a Word' button silently never renders. Finally, langcodes/language_data 3.5.1/1.4.0 reports tag_is_valid('iau')=False and A-Z+T hard-gates its language chooser on that — but 'fau' (Fayu) is valid and IS in the bundled Ethnologue lineage data as Lakes Plain > Tariku > West.

## Findings

- **[high]** Syllable-profile analysis imposes no CV(C) / open-syllable template. Profiles are validated as a CHARACTER SET, not a shape grammar, so arbitrary VV/VVV runs and consonant clusters are legal.
  - _evidence:_ backend/core/profiles.py:34 `self.profilelegit = ['̃','N','G','S','D','C','Ṽ','V','ʔ','ː',"̀",'=','<','.']`; backend/core/profiles.py:333 `if not set(self.profilelegit).issuperset(profile): profile='Invalid'`. Empirically (I instantiated utilities/rx.py RegexDict directly with a Fayu-like sdict): 'tiaure'→'CVVVCV', 'uai'→'VVV', 'oai'→'VV' (with 'ai' a confirmed digraph), 'kirik'→'CVCVC', 'ᵐbou'→'CV', 'kwai'→'CV'.
  - _implication:_ The core profile analysis is usable for Fayu as-is. There is no Bantu canonical-shape assumption to work around.

- **[high]** The syllable model explicitly handles the vowel-sequence/hiatus ambiguity that Papuan languages force — a profile's syllable count is treated as a RANGE, not a number.
  - _evidence:_ backend/core/analysis_inputs.py:227-232 `profile_syllable_range` returns `(len(self._vowel_runs(segs)), self._individual_vowels(segs))`; :183-199 `profile_fits_class` docstring: "a syllable is one OR MORE vowels, so a vowel run can be read as one syllable or several and 'CVVCV' is legitimately 2 or 3 syllables — compatible with both C2V and C3V"; :401-407 constrain_profile comment: "A profile's count is ambiguous between its vowel-SEQUENCE count (VV=1, a diphthong) and its INDIVIDUAL-vowel count (VV=2, hiatus)." `syllable_count` (:326-334) counts maximal vowel-runs, `max(n,1)`.
  - _implication:_ This is the single best-designed part of the app for Fayu. A word like /uai/ can be sorted as 1, 2 or 3 syllables by ear and the machine will not fight the user.

- **[high]** The three syllable primitives (#C, C#, syls) and the profile-class scheme are theory-neutral and derived, not templated; clusters up to 3 are auto-offered with a by-hand escape hatch for anything rarer.
  - _evidence:_ backend/core/analysis_inputs.py:322-334 `word_initial`/`word_final`/`syllable_count`; :162-166 `compose_profile_class` → e.g. 'C2V'; :306-341 `legal_profiles_for_class(..., percap=2)` — "each C-cluster / V-run is 1..1+percap long"; docstring: "Anything rarer is set by hand on the free-entry page."
  - _implication:_ Complex codas and onsets up to CCC are offered automatically; longer ones are enterable by hand. No configuration needed.

- **[high]** The tone model is register-agnostic and value-free: it produces same/different sorting piles and cross-frame equivalence classes, never H/L/M labels. Contour tones and more than three levels are representable via Chao tone letters, with real contour interpolation in playback.
  - _evidence:_ backend/reporting/generator.py:246-250 report text: "this report should contain a decent draft of your underlying tone melody groups. It does not pretend to tell you what the values of those groups are"; backend/core/lexicon.py:2041-2160 `class Tone(Senses)` stores only opaque group ids via `item.examples[check].tonevalue(group)`; frontend/transcriber.py:135 `tonechars=['[','˥','˦','˧','˨','˩',']']` (5 Chao levels, free sequencing); io_put/sound.py:528-556 `compile()` detects `c != syl[n+1]` and interpolates hz, so falling/rising contours are synthesised. No 'H'/'L'/'M' tone constants exist anywhere in backend/, frontend/ or tasks/ (grep).
  - _implication:_ Fayu / Lakes Plain tone systems with many tonemes and contours are expressible. Group NAMES are free text; suggested labels like '[˥˥ ˨˨]' (tasks/tasks.py:1609) are only suggestions.

- **[high]** Tone sorting IS organised by (lexical category × syllable profile) slices with per-ps 'tone frames' — the Snider / Kutsch Lojenga African participatory-tonology methodology — but the frames themselves are user-authored, not built in.
  - _evidence:_ docs/RATIONALE.md:12-18 cites Kutsch Lojenga 1996, Snider 2014/2018 and Marlo 2013 ("Verb tone in Bantu languages"); backend/core/sorting_engine.py:239 `frames=self.program.toneframes.get(self.ps)`; settings/tone_frames.py is a bare JSON ConfigManager with no defaults; `ToneFrameDrafter` (tasks/tasks.py, from :700) collects before/after text per language per ps.
  - _implication:_ Methodologically Africanist in ancestry, but nothing is hardcoded. Fayu tone frames must be invented by Seth; the app supplies none.

- **[high]** Prenasalised stops and labialised Cw are first-class: NC and CG are explicit interpretation settings, prenasalised segments are in the hardcoded inventory, and a labialised 'Cw' variant is auto-generated for EVERY consonant glyph.
  - _evidence:_ utilities/rx.py:434 `interplist=['NC','CG','CS','VV','VN'] #in this order!`; io_put/lift.py:1886-1889 `c['pn'][2]=['ᵐb','ᵐp','ᵐv','ᵐf','ⁿd','ⁿt','ᵑg','ⁿg','ᵑg','ⁿk','ᵑk','ⁿj','ⁿs','ⁿz']` with the comment "If these appear, they should always be single consonants"; plain 'mb','nd','ŋg' at io_put/lift.py:1802; io_put/lift.py:1905-1919 loops every consonant class and appends `glyph+'w'` as a longer polygraph unless the glyph already contains w/ʷ. Empirically 'ᵐbou'→'CV' and 'kwai'→'CV' once those are confirmed polygraphs.
  - _implication:_ Papuan prenasalisation and labialisation are supported. Note the asymmetry: there is no matching auto-generation of palatalised Cy/Cʲ — only 'ny' and 'gn' appear, as ad-hoc nasal digraphs (io_put/lift.py:1898).

- **[high]** BUT the digraph/polygraph CANDIDATE list is a closed, hand-curated list shaped by English, French and Cameroonian orthographies. Sequences not on it can never be declared single segments through the UI.
  - _evidence:_ io_put/lift.py:1960-1968 `x['Vdg']=['ou','ei','ɨʉ','ai', … 'yi','yu','yɨ','yʉ', #requested by Jane … 'ai','ea','ou','ay', #For English … 'ai','ei','oe','ae', # for French …]`, with `#requested by bfj` (Chufie', Cameroon) on the first row. Missing common Papuan/Austronesian VV: 'ia','ua','ao','io','iu','ui','eo','uo'. docs/POLYGRAPHS.md:6 admits it: "[A-Z+T] initially assumes that all possible polygraphs (that I've told it about) _found in the data_ are actually polygraphs". The only UI escape hatch is a mailto — frontend/config/settings_ui.py (askaboutpolygraphs): "If you expect one (already in your data) that isn’t listed here, please click here to Email me, and I can add it."
  - _implication:_ For Fayu, /ia/, /ua/, /ao/, /io/, /iu/, /ui/ will ALWAYS be analysed as two vowels and can never be declared a single nucleus. This is the most concrete Africa-shaped limitation for a Papuan language — and it is a one-line PR to io_put/lift.py `clist()`, an obvious contribution back to upstream.

- **[medium]** Non-Latin script is partially anticipated: Tibetan glyphs are already in the hardcoded segment inventory, so the design is not Latin-only in principle.
  - _evidence:_ io_put/lift.py:1801-1957 includes Tibetan syllabic consonants ('ག','ད','བ','ཀ','ཁ','ང','ན','མ','ཉ' …) and vowel signs ('ི','ུ','ེ','ོ'), plus `x['=']=['=','-','།','་']` (Tibetan affix/word delimiters) and `x['.']=['་']`. io_put/pdf_fonts.py registers Charis (SIL) for PDF output, covering IPA and Chao tone letters.
  - _implication:_ Not directly relevant to Fayu (Latin script), but it means extending the inventory for a new script is an accepted pattern in the codebase rather than a fight with the architecture.

- **[high]** The alphabet-booklet ordering feature uses phonetic feature tables that silently fall back to frequency ordering for symbols they don't know — and they don't know implosives, prenasalised units, labial-velars or retroflexes.
  - _evidence:_ backend/core/alphabet.py:47-62 `_CONS_FEAT` covers p b m ɸ β f v θ ð t d n s z ts l r ɾ ʃ ʒ tʃ dʒ c ɟ ɲ j k g ŋ x ɣ w q ʔ h y — no ɓ ɗ ʈ ɖ kp gb ᵐb; backend/core/alphabet.py:77-84 `segment_distance` returns 99.0 "when either symbol is unknown to the tables (caller's tie-break then decides)"; :99-118 `propose_page_sequence` then falls back to `-freq.get(g,0)`.
  - _implication:_ Cosmetic only (page order in a printed alphabet booklet), and the gap is symmetric — it misses African implosives and labial-velars just as it misses Papuan prenasalised units. Fayu's /β/ IS in the table.
