## Summary

A-Z+T has TWO collaboration layers, neither of which is a workflow system. (1) LEGACY (backend/core/vcs.py, 1004 lines): direct `git` subprocess (plus retired Mercurial) against the LIFT folder, with send/receive to BARE REPOS ON USB STICKS — sneakernet, no server, discovered/prompted at app open and close. (2) CURRENT (backend/core/collab.py, 1512 lines): an out-of-process DAEMON in a separate repo, `azt-collab` (shipped to phones as the "A-Z+T Collab" Android app), reached over RPC through an `azt_collab_client` package. azt hands the daemon the WHOLE serialized LIFT file and a `base_sha`; the daemon owns the git repo, does all merging, and syncs on two channels — LAN (paired peers, works with zero internet) and WAN (GitHub ONLY, via a GitHub App; non-GitHub internet remotes are refused outright). There is NO Chorus and NO Harmony: `harmony_sync.py` is a dead orphan importing an absent `harmony_client`, and Chorus appears only as damage detection (`.ChorusRescuedFile`). On Seth's disk the whole collab layer is INERT — `azt_collab_client.old` is a broken symlink to `/home/kentr/bin/...` and there is no sibling azt-collab clone, so `collab.AVAILABLE` is False and every collab test skips. The unit of collaboration is the entire LIFT file per save (explicitly "costs the same for 15 changed words as for 1500"); there is no per-entry, per-row, or per-task channel and no locking. Conflict handling is entirely daemon-side (`MERGED_WITH_LOCAL` + `n_conflicts` annotated in the merged file); azt's contribution is a carefully-tested no-clobber invariant (never advance base after a merge) plus a poll → "team changes available" → in-place reload path. Identity is ONE free-text contributor name per machine, seeded once from `git user.name`, used as the commit author and for attribution strings — that is the entire identity model. There are zero roles, zero permissions, zero per-user filtering, and zero work assignment anywhere in the codebase; `settings/contributors.py` is a 7-line credit roster printed on the alphabet-chart PDF, not user identity. The offline-first field story is real but is a RECORDING story (Android phones running the separate Collab + Recorder apps, LAN-synced, field-validated 2026-07-11), not an assignment story. The design Seth actually wants — a server assigning one word to one client at a time, groups assigned to multiple clients for verification, phones joining by QR code — is written down verbatim in docs/NEXT_GENERATION.md and has ZERO implementation.
